# design-gsq.md - GSQ 思路移植到 MXFP4（保持 type 39 / radiance fast path）

背景：AWQ（激活分布）与 GPTQ（权重改写+对角目标）两条校正路线均被端到端否决。
分析确定 radiance 约束（`type==MXFP4`、E2M1 码 + E8M0 块指数、folded-scale 前提=2 的幂）
下唯一未动的杠杆 = **离散码字分配本身**：格式一个字节不变，只换"每个权重元素选
哪个 E2M1 码"。GSQ（arXiv 2604.18556，IST-DASLab）正是这类方法的 SOTA：
Gumbel-Softmax 可微搜索逐元素网格赋值，官方明确支持"refine in-format GGUF"。

实现形态（本轮）：精确贪心坐标下降（CD），比 GSQ 的 Gumbel 松弛更强——
行独立 + 逐列增益 `dL = 2*delta*(He)_j + delta^2*H_jj` 是**精确值**而非采样近似。
目标 = 真实层输出误差 tr(E^T H E)，H 用 `llama-imatrix --hessian-dir` 采集的真实
校准 Hessian（128 chunks，ntok=65536）。

## 1. 正确性（血泪两轮的 bug 已清零）
- `gsq_verify2.py`：单列 16 候选的向量增益 vs 逐行暴力重算，K=64/96/128、
  多 j、5 组规模全部 PASS（rel err ~1e-7，argmin 一致率 1.0000）。
- 修过的 bug：H packed 镜像方向（lower，不是 upper）；`e[:,j]` 是 numpy **视图**
  导致 delta 恒 0 污染 EH（clone 修复）；rank-1 更新未零化未接受行（补 `d[~upd]=0`）。
- 每轮 loss 用独立全量重算核对（incremental == einsum，一致）。

## 1.1 严重 bug：python grid_search 的符号错误（重标定所有数字）
`mi = argmin |x/s - MAG|` 中 MAG 表只有 8 个正值，对 x<0 距离单调增 -> **所有负元素
被量化成 0**。单元测试（gsq_unit.py）暴露：修复前只有 50% 码字 nearest-at-exponent，
修复后 100%。影响：修复前报告的 "trEHE -98%" 大部分是在**修我自己的这个 bug**（CD
把被错误置零的负元素翻回正确码），不是真实收益。修复后在**真实 H** 上重跑：

```
trEHE  7.87e5 -> 1.65e5   (-79.1%)     <- 仍大幅降
||E||F 2.946  -> 4.928    (+67.3%)     <- 误差能量净增（搬运特征更强）
J      6.59e5 -> 1.30e6   (+96.6%)     <- 对角代理翻倍恶化
```
谱分解（修复后）：最大 10% 特征方向 -97.4%，最小 10% 方向 +433%。搬运结论不变。

### 2.1 grid search 已是"对角目标"的全局最优（无免费午餐）
穷举全部 255 个 E8M0 指数 vs C++ 的 13 候选窗（`scale_window.py`，blk.0.attn_qkv）：
**改善 0.0000%**。imatrix grid search 对它自己的 J 目标已无剩余空间——
任何进一步收益只能来自换目标（用 H 非对角），而这正是下一步。

### 2.2 CD 大幅降 trEHE，但谱诊断证明它是"藏误差"不是"减误差"（修复基线后仍成立）
blk.0.attn_qkv（512 行子集，2 轮，CPU 61s）：

```
trEHE  2.04e8 -> 3.15e6   (-98.5%)     <- H 加权目标
||E||F 1.86e1 -> 2.50e1   (+34.5%)     <- 总误差能量反而变大
J      2.57e7 -> 3.51e7   (+36.4%)     <- 对角代理同步恶化
```

按 H 特征带分解（lam*E^2 = 各带对 trEHE 的贡献）：

| H 特征带 | lam*E^2 变化 |
|---|---|
| 最大 10% | **-99.9%** |
| 50-90% | -58.9% |
| 10-50% | +194.5% |
| 最小 10% | **+420.0%** |

结论一目了然：CD 把误差从"校准数据看得见"的大特征方向**搬运**到
"校准数据看不见"的小特征方向。总能量 +34.5% = 纯搬运，不是减少。
推理时的输入分布一旦偏离校准语料（必发生），被藏起的误差全部暴露。
这与 GPTQ 的签名完全一致（trEH 局部改善 -> PPL -2.59% 端到端恶化）。

### 2.3 为什么这条路对 MXFP4 比 GSQ 论文场景更糟
- GSQ 论文的格式是 **per-group 浮点 scale 的整数量化**（2-3bpw INT 网格）：
  网格相对粗（4-8 级），离散重分配的自由度大、可微搜索收益明显（Q2_K 50.0->56.3）。
- MXFP4 的 E2M1 网格只有 {0,.5,1,1.5,2,3,4,6}x2 幂，且**每元素已能精确落在
  amax 最优网格点上**；grid search 对 J 全局最优（2.1）。剩下的优化空间
  全部集中在"H 非对角"方向——而实测那正是过拟合方向。
- 双端量化（A 端 fp8 per-row）使单层误差本身已含激活噪声，H 的低能量方向
  更加不可信。

## 2.4 生产基线上的正则化扫描（blk.3.attn_qkv，存储码字，H 归一化）

基线 = mix145 里 C++ 量化器实际存储的码字（无 python grid_search 干扰）：

| lam | trEHE | \|\|E\|\|F^2 |
|---|---|---|
| 0 | -94.1% | +735% |
| 10 | -85.5% | +1.4% |
| 100 | **-64.0%** | **+0.2%** |
| 1000 | -23.0% | +0.01% |

lam=100 时"能量几乎不变、trEHE 降 64%"= 典型的**谱内旋转**特征（把能量从大
特征值方向搬到小特征值方向）。它是否**跨分布保留**，只有 held-out H 能判：
held-out 与 train H 共享数据分布 -> 小特征方向同样"看不见"，若搬运则 held-out
不降甚至升；若真减误差则同比例下降。决定性实验已排队（hess-holdout 收集中，
chunk 128-167，与训练 chunk 0-127 语料不相交）。

## 2.45 跨分布探针：决定性负结果

合成实验 `gsq_crossdist.py`：构造两个激活分布 A（smooth local corr）与
B（不同相关长度 + 24 强 outlier 通道）。在分布 X 上校准 + CD 优化，评估在分布 Y：

| 训练→评估 | lam=0 | lam=10 | lam=100 | lam=1000 |
|---|---|---|---|---|
| A→A (同分布) | -79.9% | -50.9% | -15.2% | -2.0% |
| **A→B** (跨分布) | **+108%** | +2.0% | 0.0% | 0.0% |
| **B→A** (跨分布) | **+1146%** | -0.07% | -0.04% | +0.02% |

结论：**trEHE 的改善只在校准分布上成立，跨分布变成恶化**。
CD/Gumbel 优化的是 `E^T H_cal E`，H_cal 的小特征值方向在推理分布里可能变成大特征值
方向，误差被搬到那里。PPL 用 corpus.txt（英文文学），校准集是英文代码调试——
**跨分布必发生** → PPL 一定恶化（与 GPTQ 结局同构）。

正则化 lam 越大，跨分布越"安全"（0% 变化），但同时 trEHE 收益也归零——
说明**没有任何 lam 能在跨分布意义上拿到正收益**。

## 2.5 归一化 H 谱分解（关键澄清）+ GPU 管线就绪

spec_lam.py（归一化 H，生产存储码字基线，512 行）：

| lam | trEHE | \|\|E\|\|F² | small10/mid/hi/big10 特征带 (lam*E²) |
|---|---|---|---|
| 10 | -85.5% | +1.38% | +2% / +1% / +1% / **-87%** |
| 100 | -63.7% | +0.19% | +1% / +0% / -0% / **-65%** |
| 1000 | -23.7% | +0.01% | +1% / +0% / -0% / **-24%** |

修正之前"误差涌向小特征方向"的解读：那是**未归一化 H 时 lam 标定错误**的结果。
归一化后正则化 CD 的行为是：削减大特征方向能量，其他带几乎不动（+1% 级）——
这是"在总能量守恒附近，把误差从校准强权重方向挪到弱权重方向"，
弱方向增量仅 ~1%（对比未正则化时 +433%）。**性质介于"真减"与"搬运"之间，
是否跨分布保留必须由 held-out H 判定**（hess-holdout 收集中，chunk 128-167）。

- gsq_gpu.py：全模型 in-place GPU 精炼（numpy 版逐位等价验证 agree=1.0000，
  gsq_equiv.py），可断点续跑，lam 默认 100。f64 计算。
- 字节完整性验证（verify_bytes.py，已跑）：285 个 mxfp4 张量 **exponent 全部逐字节
  不变（changed=0）**、文件同尺寸（15584267968）、tensor 集合/类型/形状不变；
  271 个张量 code 有变 -> radiance fast path 前提（type39 + E8M0 格点 + repack）
  字节级不受影响，这是"走 radiance"硬约束的正向确认。
- tt-errors python 复现与 C++ 逐位吻合（5 抽检，max rel dev 4.34e-06）。
- 全量精炼实测（lam=100 rounds=2）：top-165 已完成（44 min），rest-118 进行中。
  **mean trEHE ratio 0.788（-21.2%），||E||F² mean +0.03%（能量守恒）**，
  单张量范围 -14% ~ -40%。即"守恒旋转"：总误差几乎不变，误差从校准强权重方向
  转到弱权重方向 —— 是否跨分布保留由 literature-H 与 PPL 判定。
- 已 refine 子集 J 变化 +1.17%（符合"对角让位非对角"预言）。

## 3. 判定汇总（按时间线，含自我推翻）

1. 合成跨分布（§2.45）与 tri-score（§2.95）共同定位：**收益幅度由校准分布与

   （代码 + 中英通用文本），预期落在两者之间；PPL-corpus 实验证明其机制真实。
4. J 与 PPL 第四次脱钩确认（d2 J +0.64% 同时 PPL -2.64%）——此路线选型
   **只能**用端到端 PPL/任务评测。

## 6.5 D3 电池结果：全面恶化 + 窗口粒度 bug（已修，d3b 重测中）

10 场 paired 电池（09:00 完成）：

|---|---|---|---|---|
| eval-gen（混源） | 7.1435 | 7.6490 | **+7.1%** | 7.5104 (+5.1%) |
| eval-zh | 11.5283 | 12.4963 | **+8.4%** | - |
| eval-code | 9.1579 | 9.3692 | **+2.3%** | - |
| eval-wiki | 8.0747 | 8.1467 | +0.9% | - |
| corpus.txt（文学） | 6.7461 | 6.6597 | -1.28% | **6.5678 (-2.64%)** |

模式：每个模型在**自己校准窗口命中的分布**上改善、在其他分布恶化
（d2 只在 prose 上赢、d3 只在文学上小赢），且跨分布伤害 > 本域收益。
机制图景：lam=100 的"守恒旋转"把误差搬到窗口 H 的弱方向；推理文本
一旦落在弱方向上，误差就爆发。匹配度假说成立，但**代价是窄化**。

**根因（自查抓到）**：校准窗口实际比设计小一个数量级——24 chunks ×
512 tok ≈ 12K token ≈ **4-8 万字符**，而 interleave 用 64KB 块轮转 ->
真实窗口只落进前 1 个块 = 单一来源（d3 H 实际 ≈ 纯 en_inst，窗口探针
cjk=0% 实锤）。之前"窗口 20MB 全混"的检查用错了窗口大小。
修复：4KB 块轮转 + 80KB 真实窗口断言（cjk 25.2%、code/en/wiki/lit/zh
标志全真，leak=0），并加进 build 脚本防回归。

d3 模型验收件补齐：
- 字节验证：285 exponent 不变、code-changed 280、文件同尺寸（15584267968）
- ENGAGE=560 / decline=369（= B145 逐项一致，decline 全为 mxfp6 策略）
- bench：pp2048 2111.0、tg128 28.04（B145 区间内）
- tt-errors 全量 J：prod 3.4919 -> d3 3.5271（**+1.01%**，280/280 变差）

d3b 链（09:19 干净重启，pgrep 自匹配死锁已修）：正确混源窗口 -> H -> refine ->
paired（gen2 同分布 + lit2 迁移对照）。若 gen2 显著改善且 lit2 不再大涨 -> "按使用分布校准"
策略成立，d3 失败是工程 bug；若 gen2 仍恶化 -> 多源窄窗口机制本身有问题
（H 条件数差 -> 旋转伤害超过匹配收益），路线按负结果收口。

## 7. GSQ 移植总判定（终）

| 路线 | 校准 | 最佳 PPL 改善 | 判定 |
|---|---|---|---|
| r1/r2 | 代码（B145 原校准） | -0.48% | 未达 0.5% 线 |
| lit-calib | 评测文本本身 | **-2.73%** | 泄漏上界，仅机制证据 |
| d2 | 同书非评测章节 | **-2.64%** | 文学域可部署最优 |
| d3 | 混源（窗口=单源 bug） | 全域 +2~8% 恶化 | 工程失败样本 |
| d3b | 混源（窗口已修） | 同分布 +5.8% 恶化 | **多源混窗机制性伤害，判死** |

**结论**：MXFP4 离散码字精炼（GSQ 思想，CD 实现）在"单一窄域校准"下有效
（d2：同域 -2.6%、跨域 -1.3%，radiance/体积/吞吐全保），在"多源混合校准"
下机制性失败（H 病态 -> 旋转伤害 > 匹配收益，且与 lam 无关地存在于 1e8~0
全区间）。对本项目：B145 的代码校准与其真实 workload（代码/技术文本为主）
匹配度本就高，可收割空间 ~0.5% 以下；**生产模型维持 B145**，d2 形态保留
为"特定域部署时按域校准"的选件（管线全备，一次 ~1.5h）。

方法论遗产（design-gsq.md 全程记录）：
- J（tt-errors）与 PPL 四次脱钩，代理指标在该路线不可选型
- "守恒旋转"（fro 不变 + trEHE 大降）= 把误差搬进校准盲区，跨分布即爆发
- imatrix 校准窗口 = chunks×512 tok，语料必须按**这个窗口**做混合粒度设计
- pgrep -f 自匹配、ssh 会话清理带走 setsid 子进程：链式实验必用文件标志+
  看门狗，不用进程名探测
